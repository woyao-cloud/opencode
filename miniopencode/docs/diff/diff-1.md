2. 架构差异

miniopencode 是 opencode 的精简重构版，核心思路：

- 3 个包：core（工具函数）、llm（LLM 协议）、opencode（主程序）
- CLI 入口：yargs（非 opencode 的 @effect/cli）
- 运行时：ManagedRuntime.make(AppLayer) — 与完整版相同的 Effect Layer 模式，但 Layer 数量少得多（~15 个 vs 50+）
- bootstrap.ts 只有 33 行，而完整版 app-runtime.ts 有 144 行

3. 已实现 vs 缺失的模块

5. 设计哲学差异

miniopencode 的设计目标是最小可行实现：
- 只保留核心链路：CLI → Session → Prompt → LLM → Tools → Persistence
- 每个模块只实现最必要的功能
- 使用 yargs 替代 @effect/cli 减少复杂度
- 依赖从 50+ 减少到 6 个

完整版 opencode 是生产级 AI 开发工具：
- 完整的 TUI 界面（SolidJS）
- 多 Provider 路由和协议抽象
- MCP/ACP 协议支持
- PTY 终端、LSP 集成
- 控制平面（多 workspace 管理）
- 同步/分享/账号系统

6. 代码复用关系

miniopencode 的很多模块是完整版 opencode 的简化移植：
- effect/ 目录 — 简化版 Effect 运行时（instance-ref, instance-state, run-service, bridge）
- session/ 目录 — 简化版 Session 系统（无 compaction/retry/revert 等高级功能）
- tool/ 目录 — 6 个核心工具 vs 完整版的 20+
- permission/ 目录 — 核心权限引擎已实现，但缺 ask/reply UI 事件流

结论：miniopencode 是 opencode 的功能子集 + 架构简化版，核心骨架完整（~46% 模块覆盖率），但外围高级功能（MCP/PTY/LSP/TUI/多 Provider）尚未实现。适合学习 Effect-TS 架构模式或作为轻量级 AI 工具使用。
