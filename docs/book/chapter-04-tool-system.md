# 第 4 章 · 工具系统设计

工具系统是 opencode 让 AI 能够"动手做事"的关键。本章深入工具的定义、注册、执行、权限和 UI 渲染机制。

## 4.1 工具的两种定义模式

opencode 的工具系统支持两种定义模式，分别适用于不同的场景。

### Typed 模式（编译时类型安全）

当工具的输入输出结构在编码时已知，使用 Typed 模式。开发者提供 Effect Schema 定义的参数和返回值类型：

- **parameters**：工具输入参数的 Schema。例如 Bash 工具的参数包括 `command`（字符串）和 `workdir`（可选字符串）
- **success**：工具成功返回值的 Schema。例如 Bash 工具的返回值包括 `output`（字符串）和 `exitCode`（数字）
- **execute**：工具的执行函数，接收解码后的参数，返回 Effect 封装的执行结果

Typed 模式的优势是编译时类型检查——如果你在 execute 函数中访问了参数 Schema 未定义的字段，TypeScript 编译器会报错。

### Dynamic 模式（运行时动态加载）

当工具的 Schema 来自外部来源（MCP 服务器、插件清单、动态配置）时，使用 Dynamic 模式。开发者提供原始 JSON Schema 而非 Effect Schema：

- **jsonSchema**：工具的 JSON Schema 定义
- **execute**：执行函数，接收 `unknown` 类型的参数（需要自行验证）

Dynamic 模式用于 MCP 工具集成——MCP 服务器在运行时声明其工具列表和 Schema，opencode 将其包装为 Dynamic 工具。

### 工具的内部结构

每个工具（无论 Typed 还是 Dynamic）内部都携带：
- `_decode`：将 LLM 返回的 JSON 参数解码为类型安全输入的 Effect
- `_encode`：将执行结果编码为 JSON 的 Effect
- `_definition`：预计算的 ToolDefinition（名称、描述、JSON Schema），避免每次调用时重建

## 4.2 工具生命周期状态机

每个工具调用在 opencode 中经历严格的状态转换：

```text
pending ──→ running ──→ completed
                │
                └──→ error
```

### Pending

AI 请求调用工具时，工具状态为 `pending`。此时只有工具的原始输入（AI 生成的 JSON 字符串），尚未解码和执行。在 UI 中，pending 状态的工具通常显示为"准备中"。

### Running

工具通过权限检查并开始执行后，状态变为 `running`。此时：
- 输入已被解码为结构化参数
- 执行函数正在运行
- 可能产生中间输出（如 Bash 命令的实时输出流）

在 UI 中，running 状态的工具显示为进行中（⚙ 图标或自定义渲染）。

### Completed

工具执行成功完成，状态变为 `completed`。此时包含：
- 完整的结构化输出
- 可能的文件附件（如 Read 工具返回的文件内容）
- 执行耗时

### Error

工具执行失败，状态变为 `error`。此时包含：
- 错误信息
- 截断的输出（如果有）
- 错误发生的时间点

## 4.3 工具审批（Permission）机制

opencode 不会让 AI 随意执行敏感操作。每个工具调用都需要通过权限检查。

### 权限键

权限不是按工具名单独设置的，而是按**权限键**分组。多个工具可以共享同一个权限键：

| 权限键 | 涵盖的工具 |
|--------|-----------|
| `bash` | Bash（执行 Shell 命令） |
| `edit` | Write、Edit、ApplyPatch（修改文件） |
| `read` | Read、Glob、Grep（读取文件和搜索） |
| `web` | WebFetch、WebSearch（网络访问） |
| `task` | Task（派发子 Agent） |
| `skill` | Skill（调用技能） |
| `lsp` | Lsp（语言服务器操作） |

### 权限规则

权限配置采用"允许列表"模式：默认所有操作都需要审批，用户可以为特定权限键设置规则：
- **once**：仅本次允许
- **always**：在本次 Session 中始终允许
- **deny**：拒绝

权限规则可以限定到特定模式（pattern），例如只允许 Bash 在 `src/` 目录下执行。

### 审批流程

当 AI 调用工具时：
1. 框架查找该工具对应的权限键
2. 检查用户是否已对该权限键设置了规则
3. 如果已有 `always` 规则 → 直接执行
4. 如果已有 `deny` 规则 → 拒绝执行，返回错误给 AI
5. 如果没有规则 → 暂停执行，向用户展示权限请求，等待用户决策

在 CLI 模式下，权限请求通过终端交互展示；在 TUI 模式下，通过对话框展示；在非交互模式下（如 `--dangerously-skip-permissions`），可以自动批准或拒绝。

## 4.4 关键工具详解

opencode 内置了约 20 个工具。以下是几个核心工具的设计要点：

### Bash —— 执行 Shell 命令

最强大也最敏感的工具。设计要点：
- 命令在子进程中执行，通过 PTY（伪终端）获得完整终端体验
- 实时输出流式返回，支持 ANSI 颜色码
- 超时保护（默认 2 分钟）
- 环境变量隔离（继承宿主环境但可覆盖）
- 工作目录默认为项目根
- 输出截断：超过一定长度的输出被截断，防止上下文膨胀

### Read —— 读取文件

设计要点：
- 支持读取整个文件或指定行范围
- 支持读取图片文件（返回 base64 编码）
- 支持读取 PDF 文件（返回文本提取结果）
- 读取结果可能触发指令文件发现（见第 6 章）
- 输出截断：大文件只返回指定范围

### Write / Edit / ApplyPatch —— 修改文件

三个文件修改工具各有适用场景：
- **Write**：创建新文件或完全覆写已有文件
- **Edit**：精确字符串替换（需要 old_string 和 new_string 完全匹配）
- **ApplyPatch**：应用 unified diff 格式的补丁

三者共享 `edit` 权限键。Edit 工具的设计特别强调精确匹配——old_string 必须与文件内容完全一致（包括缩进），这避免了 AI 模糊修改导致的意外破坏。

### Glob / Grep —— 代码搜索

- **Glob**：文件模式匹配（如 `**/*.ts`），返回匹配的文件路径列表
- **Grep**：内容搜索（基于 ripgrep），支持正则表达式、文件类型过滤、上下文行

### Task —— 派发子 Agent

这是多 Agent 协作的关键工具（详见第 9 章）。Task 工具允许主 Agent 将子任务派发给 Subagent：
- 指定子任务的描述和期望输出
- 指定使用的 Subagent 类型
- 子 Agent 在独立上下文中运行
- 结果返回给主 Agent 继续处理

### Question —— 向用户提问

当 AI 需要澄清需求时，可以使用 Question 工具向用户提出多选题。用户的选择作为工具结果返回给 AI。

### TodoWrite —— 任务列表管理

AI 可以使用 TodoWrite 工具创建和更新任务列表，跟踪复杂多步骤任务的进度。这不是给用户看的 TODO，而是 AI 自身的执行计划。

## 4.5 工具输出截断策略

工具输出可能非常长（如 Grep 搜索返回数千行结果、Bash 命令输出大量日志）。如果不加控制，这些输出会迅速填满上下文窗口。

opencode 的截断策略包括：

- **字符数限制**：每个工具的输出有最大字符数限制，超出部分被截断
- **行数限制**：某些工具（如 Grep）限制返回的行数
- **截断标记**：被截断的输出末尾添加截断标记，告知 AI 输出不完整
- **智能截断**：优先保留结果的开头和结尾，中间部分被省略（因为关键信息通常在两端）

截断在工具执行完成后、结果注入消息历史前进行。

## 4.6 工具注册表与 UI 渲染

每个工具不仅有执行逻辑，还有**UI 渲染规则**。这些规则定义在 `packages/opencode/src/cli/cmd/run/tool.ts` 中的 `TOOL_RULES` 注册表。

### 渲染规则结构

每个工具的渲染规则包含：

- **view**：控制哪些阶段显示输出（如 `{ output: true, final: true }`）
- **run**：工具执行中的内联渲染（图标 + 标题 + 描述）
- **scroll**：工具完成后的滚动摘要（分 start/progress/final 三个阶段）
- **permission**：权限请求时的展示信息
- **snap**：工具快照（用于会话恢复）

### 渲染模式

工具在终端中有两种渲染模式：

- **inline**（内联）：工具信息显示在一行中，如 `→ Read src/main.ts:1-50`
- **block**（块）：工具信息占据一个可折叠的块，包含完整的输出内容。如 Bash 命令的输出、Read 文件的完整内容

### 示例：Bash 工具的渲染

- **run 阶段**：显示 `$ command`（命令文本）
- **progress 阶段**：显示实时输出流
- **final 阶段**：显示 `bash completed (exit 0) · 1.2s`（退出码 + 耗时）

### 示例：Task 工具的渲染

- **run 阶段**：显示子任务描述
- **progress 阶段**：显示子 Agent 的执行状态
- **final 阶段**：显示子任务完成摘要

## 本章小结

opencode 的工具系统通过类型安全的定义模式、严格的生命周期状态机、分组权限控制和统一的 UI 渲染规则，构建了一套完整且可扩展的工具执行框架。工具不是外挂插件，而是框架的一等公民——每个工具从定义到执行到展示都有明确的契约。这套设计使得 AI 能够安全、可控地操作文件系统、执行命令和协调子任务。
