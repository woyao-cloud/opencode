# 第 6 章 · Memory 体系

Memory 体系解决的是"AI 如何记住跨会话的信息"这个问题。opencode 的 Memory 不是单一的记忆存储，而是一个分层的、以文件系统为基础的、自动与手动相结合的体系。

## 6.1 指令文件系统

指令文件是 opencode Memory 体系的核心载体。它们是项目中的 Markdown 文件，包含给 AI 的上下文信息、行为规范和项目知识。

### 两种指令文件

opencode 识别两种指令文件：

- **AGENTS.md**：opencode 原生的指令文件格式。可以放在项目的任意子目录中，为不同代码区域提供不同的上下文。
- **CLAUDE.md**：兼容 Claude Code 的指令文件格式。功能与 AGENTS.md 类似，确保从 Claude Code 迁移的用户可以复用已有配置。

框架同时支持两种格式，加载时合并处理。

### 层级发现机制

指令文件的发现遵循"从近到远"的层级原则：

1. **全局级别**：`~/.claude/CLAUDE.md` 和 `~/.config/opencode/AGENTS.md`（用户级别的全局指令，对所有项目生效）

2. **项目根级别**：项目根目录下的 `AGENTS.md` 和 `CLAUDE.md`（对整个项目生效）

3. **目录级别**：当 AI 读取某个子目录中的文件时，框架从该文件所在目录向上走到项目根，沿途寻找 `AGENTS.md` 和 `CLAUDE.md`。找到的指令文件被注入当前消息的上下文。

这种层级设计意味着：
- 项目根下的 `AGENTS.md` 可以定义全局性的项目规范（"这个项目使用 TypeScript 严格模式"）
- `src/auth/AGENTS.md` 可以定义认证模块的特定规范（"所有认证逻辑必须通过 AuthService 接口"）
- AI 在处理 `src/auth/login.ts` 时会同时看到根级别和 `src/auth/` 级别的指令

### 注入时机

指令文件的注入发生在两个时机：

1. **会话启动时**：全局级别和项目根级别的指令文件在 System Prompt 组装阶段被注入（见第 3 章）

2. **文件读取时**：当 AI 使用 Read 工具读取某个文件时，框架检查该文件路径的目录链，发现新的指令文件后注入当前消息。这确保了 AI 在处理特定代码区域时能看到相关的上下文规则。

### 去重机制

框架维护一个"已注入文件路径"集合，确保：
- 同一个指令文件在同一条 Assistant 消息中只注入一次
- 已被压缩（compacted）的消息中的文件路径不再触发注入
- System Prompt 阶段已注入的全局/根级别文件不会在后续读取时重复注入

## 6.2 跨会话持久化

opencode 的配置和状态在多个层级持久化：

### Global 级别

存储在用户配置目录（`~/.config/opencode/` 或平台等效路径）：
- **config.json**：全局配置（默认模型、共享设置、指令 URL 等）
- **agents/**：用户自定义的 Agent 定义
- **AGENTS.md**：全局指令文件

Global 级别的数据对所有项目生效，跨 Session 持久化。

### Workspace 级别

存储在项目目录下的 `.opencode/` 中：
- **config.json**：项目级配置（覆盖全局配置）
- **agents/**：项目自定义的 Agent 定义
- **AGENTS.md**：项目级指令文件

Workspace 级别的数据仅对当前项目生效，跨 Session 持久化。

### Session 级别

每个 Session 的数据存储在 Workspace 存储中，以 Session ID 为键：
- 消息历史
- 权限规则
- 模型和 Agent 选择
- 压缩历史

Session 数据跨会话持久化——用户可以关闭终端、重启电脑，然后通过 `--continue` 或 `--session <id>` 恢复之前的对话。

## 6.3 会话内记忆：自动提取

opencode 有一种轻量级的"会话内记忆"机制：自动追踪 AI 已经读取过哪些文件。

### 工作原理

当 AI 使用 Read 工具读取文件时，框架记录该文件的路径。在后续的消息构建中，这些已读文件路径被用于两个目的：

1. **避免重复注入指令**：如果某个指令文件已被读取，不再重复注入
2. **上下文优化**：已读文件的信息可以被更高效地引用，而非重新发送完整内容

### 生命周期

会话内记忆的生命周期与 Session 绑定：
- Session 活跃期间，已读文件集合持续增长
- Compaction 发生时，被压缩的消息中的文件引用被标记为 `compacted`，不再参与去重判断
- Session 结束时，已读文件集合随 Session 数据一起持久化

## 6.4 指令的远程加载

除了本地文件，opencode 支持从远程 URL 加载指令内容。

### 配置方式

在项目或全局配置中指定 `instructions` 字段：

```json
{
  "instructions": [
    "https://example.com/coding-standards.md",
    "https://internal.company.com/project-guidelines.md"
  ]
}
```

### 加载机制

- 远程指令在会话启动时通过 HTTP GET 获取
- 获取超时为 5 秒（避免阻塞会话启动）
- 获取失败时静默跳过（不阻塞会话）
- 内容被缓存到内存中，同一 Session 内不重复获取
- 远程指令与本地指令文件的内容合并，一起注入 System Prompt

## 6.5 Memory 的清理与生命周期

### 日志轮转

日志文件（见第 7 章）有自动轮转机制：保留最近 10 个日志文件，旧文件被自动删除。这防止日志无限增长占用磁盘。

### Session 归档

用户可以将不再活跃的 Session 归档。归档的 Session：
- 从默认 Session 列表中隐藏
- 数据完整保留
- 可以随时取消归档恢复

### 指令文件更新

指令文件是普通的 Markdown 文件，用户随时可以编辑。框架在下次会话启动或下次文件读取时自动加载最新内容，无需重启或刷新。

---

## 本章小结

opencode 的 Memory 体系以文件系统为基础，通过层级发现、自动提取、远程加载和跨会话持久化，实现了从"项目全局知识"到"会话内上下文"的多层记忆。AGENTS.md / CLAUDE.md 的层级发现机制是其最独特的设计——AI 在处理不同代码区域时自动看到不同的上下文规则，就像人类开发者在不同模块间切换时会参考不同的文档。这套体系不需要向量数据库或复杂的 RAG 管道，而是利用文件系统本身的层级结构来实现"正确的信息在正确的时机出现"。
